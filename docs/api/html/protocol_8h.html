Detailed Description

IGNACC ASCII line protocol: parse commands, format responses.

Pure C, no ESP-IDF dependencies, fully host-testable.

The protocol knows the command grammar, not the board. IN<n> accepts n = 1..PROTO_MAX_CHANNELS; the caller (app_fsm) decides whether channel n exists on this board and ignores it otherwise. This is what lets the channel count be a build setting without touching this module.

Command Response
IN<n>_ON / IN<n>_OFF IN<n>_ON_OK / IN<n>_ON_FAIL / ...
ALL_ON / ALL_OFF ALL_ON_OK / ALL_ON_FAIL / ...
HeyU Hello IGNACC v<version> READY

| STATUS | STATUS IN1=<ON|OFF> ... IN<count>=<ON|OFF> | | anything else | UNK_NACK |

Received lines have their terminator stripped before parsing. Every formatted response ends with "\r\n".

◆ proto_parse()

proto_cmd_t proto_parse ( const char * line,
size_t len )

Parse one received line.

Matching is exact and case-sensitive. Channel numbers are plain decimal without leading zeros: IN1_ON and IN12_OFF are valid, IN01_ON, IN0_ON and IN17_ON are not. Embedded NUL bytes never match.

Parameters
lineReceived bytes, terminator already stripped. Need not be NUL-terminated. May be NULL.
lenNumber of bytes in line.
Returns
The command. kind is PROTO_CMD_NONE for anything that is not a valid command (including a NULL line).
